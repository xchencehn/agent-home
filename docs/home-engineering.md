# Agent Home：项目自有的持久工作环境

> **一句话结论：** Agent Home 是由项目或组织拥有、独立于具体模型与 Harness 的持久工作环境；
> Agent 可以更换，Harness 可以升级，但项目的目标、知识、状态、资源、权限、证据和责任必须持续积累。

## 愿景与动机

模型能力快速进步后，开发者创造的可通用方法会不断被更低层吸收：推理套路可能进入模型训练，工具
调用、上下文压缩、任务分解和多执行体协作可能进入 Harness，Skill 与工具接口可能进入开放标准。
因此，围绕某一代模型精心搭建的通用脚手架可能很快成为平台默认能力。

这并不意味着开发者的价值消失，而是工作重心上移：定义值得完成的目标，维护项目事实和历史决策，
组织跨系统资源，配置权限与责任，规定什么证据足以验收，并设计面对未知时如何澄清、探索和转向。
这些能力高度依赖具体项目、组织和责任关系，不能由通用模型替项目一次性决定。

所以我们提倡一种 HOME ENGINEERING：

> 模型提供智力，Harness 提供行动能力，Home 提供项目工作能力。

> 通用能力会被平台吸收，项目能力必须由开发者掌握。

> Agent 可以更换，Harness 可以升级，Home 持续积累。



## 基本概念与边界

### LLM

LLM 提供统计推理、理解和生成能力。它可以包含通过训练获得的通用知识与策略，但不自动拥有当前
项目的实时事实、权限、资源状态、验收责任和跨会话工作历史。

### Harness

Harness 是使模型能够作为 Agent 行动的运行系统，负责输入处理、上下文组织、工具调用、行动循环、
结果返回，以及可能的压缩、恢复、规划和多执行体编排。Claude Code、Codex 或其他运行产品属于这一
层的代表，而不是 Agent Home 的同义词。


### Agent Home

Agent Home 保存的是项目持续存在的工作能力。`AGENTS.md` 的内容属于 Home 的规则，Harness 寻找并
加载它的机制；一个项目的知识与脚本属于 Home，按需发现和注入的机制属于 Harness；
任务状态和证据属于 Home，模型在一次推理中读取它们形成工作上下文。


Model 与 Harness 可以来自同一个厂商，但不同 Agent Home 会使 Agent 获得不同的情境化工作能力。


# Project

Project 是我们需要让 Agent 去操作的对象，例如一个代码库，一个PPT Word 目录等等。 Agent Home 是对 Agent 的
管理和能力加持，这部分和操作对象分离。

本仓把这条边界落在 `.code/`：目标代码仓放在 `.code/` 下并被 Git 忽略，自己提交自己的历史；Home 只登记
它的目录、来源和 Task 分支。一个 Task 对应一个代码分支，多个 Task 并行时用 Git 工作树隔离，完成后合入
主分支。细节见 [代码仓与并行工作区](code-workspace.md)。



## 方案

### Home 保存七类项目能力

| 能力 | 回答的问题 |
| --- | --- |
| 目标与边界 | 为什么做、做到什么程度、哪里不能越界 |
| 知识与技能 | 项目知道什么、有哪些可重复的方法 |
| 持久工作状态 | 已经做到哪里、验证或否定了哪些方向 |
| 资源与能力 | 可以使用哪些代码仓、设备、系统和人员 |
| 权限与治理 | 谁可以读取、修改、发布、审批和回滚 |
| 证据与验收 | 什么事实支撑结论，什么仍然没有被证明 |
| 探索与行动导航 | 面对未知时怎样澄清、试探、选择和转向 |

这七类能力共同构成“项目工作能力”。只有规则没有状态，无法恢复；只有状态没有证据，无法相信；只有工具
没有权限，无法负责；只有计划没有探索导航，遇到未知就会僵化。

### 本仓是一个 Agent HOME 示例

快速使用：

```bash
git clone https://github.com/xchencehn/agent-home.git my-project
cd my-project
codex  # 或 claude
```

本仓提供了 `Task/Loop/Run`协议用于记录Agent轨迹、 `grill` 用于辅助用户设计梳理、 `next_action` 用于指导Agent探索方向、`evidence-checkpoint` 用于对Agent工作的判定：

- Task 保存长期目标；Loop 保存一个可证伪方向；Run 保存一次执行结果；
- grill 设计梳理只在目标、范围、验收或转向条件仍不清楚时触发；
- next_action 从当前行动前沿只选择一个有完成条件的动作，并在新证据到来后重算；
- evidence-checkpoint 只保存会改变路线、支撑结论或用于恢复的事实。

它们不等于 Agent Home 本身，也不因为被实现就自动证明有效。它们是当前可运行、可替换、应继续用强基线
检验的参考方案。

 

## 小结

> 不要把项目能力塞进某一个 Agent，要把它建设在 Agent Home 中。

> Agent 可以更换，Harness 可以升级，Home 持续积累。
